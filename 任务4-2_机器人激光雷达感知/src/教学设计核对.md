# 激光雷达与点云：教学设计核对

核对日期：2026-10-16。依据本章《任务4-2》与“来源/09_4.机器人激光雷达感知（2课时）.txt”，并查看以下厂商、标准机构和 PCL 一手资料。此文件是教学审查，不是已通过的浏览器验收报告。

## 本页应当回答的核心问题

学生需要亲手看见“传感器按方向测距 → 留下带坐标的离散点 → 在共同坐标系中解释点的分布 → 对有限证据作判断”。点云不应成为扫描器旁边随机飘动的一团装饰。页面的光束终点、生成点、点表、取点读数、导出数据应来自同一份测量结果。

“点更多”有两种容易混淆的来源：采集时发射更多方向；显示时把已有点画得更大/更亮。两者必须分成不同的控件，显示点大小不改变点数或探测结论。点密度更高也不自动提升每次测距的准确度；几何覆盖、随机波动、系统偏差与坐标配准应分开解释。

建议保留第一版自身状态感知的大模型、右侧操作台、下方实验卡的节奏；中心场景是透明剖开的扫描雷达与可点选的环境点云。默认蓝白色，保留少量区分扫描来源的青/蓝色。所有入口可独立开始。

## 必须准确的概念

1. **飞行时间与点坐标。** 以脉冲 ToF 为例，`r = c × Δt / 2`，Δt 是往返时间。假设理想共点光学原点，Z 向上，θ 为从 X 正向朝 Y 正向的方位角、φ 为仰角：`x = r cosφ cosθ`，`y = r cosφ sinθ`，`z = r sinφ`。传感器世界位置另加平移，安装方向另加旋转。真实产品还需要自身的光束角度和光学原点标定，不把课堂公式宣称为任何厂商的完整解码器。演示慢放不是实测传播时长。
2. **二维与三维。** 静止单线扫描通常描述一个平面截面；多线在不同垂直角度取样。移动单线扫描配合准确的同步位姿，也能累积三维点。把相同平面旋转显示不会产生缺失高度信息。点云保存 XYZ 并不保证点的分布具有三维覆盖。
3. **密度与精度。** 理想等距圆周上，相邻束终点弦长 `s = 2r sin(Δθ/2)`；小角度可近似 `rΔθ`（弧度）。墙面上沿墙点间距还与入射方向有关，不能把圆弧公式说成所有表面的精确点间距。角步进改变时重新生成角度、求交，不能用随机删点伪装。
4. **有效回波与未知。** 当前模型只取最近有效几何交点；不穿透前方不透明挡板。没有回波可能是未被射线覆盖、遮挡、超出范围或无法可靠接收，不等于没有物体。真实传感器也存在多回波机制；“只取最近交点”必须标为本教学模型的选择。
5. **颜色不是材料答案。** 高度色来自 Z 数值映射；扫描来源色用于区分 A/B；原始 RGB 需要文件具有该属性；回波强度不是可见光照片，也不能据此直接认定材料。当前几何模型若无光学仿真，不能把常量或距离函数伪装成实测反射率。
6. **相机与采集位姿。** 拖动相机只改变观察已有数据的视角，点数不增加。移动传感器并重新扫描才增加观测；合并前以 `p_world = R p_sensor + t` 置于共同坐标系。已知仿真姿态变换不叫做已实现 SLAM 或自动配准。
7. **量测与通行范围。** 同坐标、同单位、同一有效截面、两侧实际边界，才可将两点距离解释为截面净宽。0.60 m 机器人加两侧各 0.10 m，需求 0.80 m；0.90 m 截面总余量 0.10 m，0.70 m 缺 0.10 m。结论仅限该截面与教学条件，不能批准全程通过。

## 四个学生参与实验

### 实验一：一束光如何成为一个点

**预测**：只知道“距离 3 m”能唯一定位点吗？往返时间为什么不能直接乘光速当距离？

**操作**：学生拖动方向盘或点选目标表面，先单束慢放：发射→到达最近表面→回波返回→出现一个带编号的点。保留往返路径虚线，但射线不越过命中表面。改变方位角和仰角，再发出下一束；提供一步发一束和一圈扫描。

**证据**：雷达位置、方向角、单程距离、往返时间（ns）、传感器坐标与世界坐标、点号和命中物体。点云计数随实际命中增加；未命中应显示“本方向无有效回波”，不造一个最远距离假点。

**结论**：方向与距离共同确定点；很多有效测距点构成点云。示例 `r = 3 m → Δt ≈ 20.014 ns`（取精确光速 299792458 m/s），回波动画时间另标“教学慢放”。

**挑战及证据要求**：至少选择两个方向、保存不同坐标的点后作答。错误答案允许重试，不阻止切换实验。第一次单束交互应在 1–2 次点击内完成，避免学生先填表才能看到模型。

### 实验二：点多了，就一定测得更准吗

**预测**：同位置的细柱在 10° 扫描中没有点，是否意味着细柱不存在？把点绘制半径变大，是否算增加测量？

**操作**：固定雷达、场景、距离及噪声，依次以 10°、1° 发射新一圈扫描；真实比较每个角度。将细柱移到更远/更近的已知距离，重新扫。另可切换单层和多层，或单独打开“模拟测距波动”，不把所有变化绑到一个“质量”滑块。

**证据**：角步进、发射束数、有效回波数、细柱命中数、同一距离的理论束间弦长。固定条件对比至少两条记录。理想同一真值表面误差仍为零；若加模拟误差，标清模型、单位和可复现条件。

**结论**：更细角采样帮助覆盖小物体，单次距离误差是另一项指标。多层增加垂直覆盖，却仍有层间空隙，不能承诺一定检测所有低矮物或悬空物。

**补充参与**：学生拉高扫描平面，看低垫块从点云中消失，再降低平面复测；用机器人整个高度的半透明包络解释为何一张清空截面不够。

### 实验三：转动画面，还是换位置补扫

**预测**：已有点云旋转 180°，会出现挡板背后的新点吗？

**操作**：在 A 位置扫描并保留蓝色点；只拖动相机，观察点数保持不变。换到 B 再扫，新点用青色；可以单独显示 A、B 和叠加。明确固定场景与角步进。可切换“暂未变换的传感器坐标”和“已知姿态变换后的共同坐标”，让学生看到同一墙面的错位与对齐。

**证据**：两次传感器位置/朝向、A/B 点数、板后目标命中数、至少一处新增证据。导出每个点的扫描来源、传感器坐标和世界坐标。显示教学几何参照时用浅灰线并持续标“场景真值，非观测点”。

**结论**：视角变换仅帮助查看；改变采集位置可能减少遮挡，但叠加后仍不能把所有没点区域填成已知空地。姿态准确与时间对齐是合并点云的前提；本页已知位姿变换不是自动识别配准。

### 实验四：在点云里测量一个截面

**预测**：两点距离是否总是“通道宽度”？高度着色中两个相同颜色点是否意味着同种材料？

**操作**：进入规定截面①/②，自主点选左右边界 P1/P2，必要时切俯视/侧视复核端点。展示三维坐标差与距离，输入或选择 0.60 m 机器人宽和 0.10 m 侧向预留。鼓励故意选两个前后错位点，观察纵向差。提供原始色（有属性时）、高度色和扫描来源色。可导入自己的点云练习。

**证据**：数据来源、单位、原始点号与原始坐标、显示世界坐标、端点所属表面、截面编号、三维距离、所需净宽和余量。导入数据没有既定截面语义时，只称“所选两点距离”，不自动判断通道。

**结论**：数据意义依赖坐标、单位与端点语义。指定截面可提出有范围的结论；未知处保留复核建议。

## 点云导入及导出的必要约束

- 数据来源在场景、记录和导出中保持可见：教学几何仿真 / 随页分发的真实样本（若有）/ 用户导入。不能将真实样本归因到机器人当前正在扫描的教学场景。
- 支持格式必须与实际解析器一致。例如仅支持 ASCII PLY/PCD，就在文件框旁写清楚；遇到 binary / compressed、缺失 XYZ、非有限值、空数据和超大文件，给明白的错误。CSV 须选列、单位；空字符串不能自动变成零。
- 单位是用户确认的元数据；PLY/PCD 的常规坐标字段不能可靠保证“必为米”。例如原始点 `[1000,0,0]` 与 `[2000,0,0]`，单位 mm，距离应为 1 m，原始坐标读数仍应为 1000/2000 mm。
- 原始点不可因居中、缩放、坐标朝向切换被覆写。保存 `p_source` 与 `p_world`，显示变换说明。对大坐标用保留双精度的原始数组，渲染减去局部原点避免浮点抖动；不能把 Three.js Float32 缓冲当作唯一量测数据。
- 缩放视图不改变量测距离；切着色不改变 XYZ；过滤或抽稀须注明原始/当前显示点数，并保持可追溯点号。取点以当前可见点为准，避免射线选到不可见背景造成误导。
- 导出需包含格式/单位/来源、采集条件、所选点与原坐标、转换说明、实验记录及判断。不要只导出屏幕坐标或变换后坐标。

## 第一手参考资料及页内适用处

1. [SICK：LiDAR Basics](https://sickag.github.io/sick_lidar_developer_guide/lidar-basics/)：ToF、角分辨率、单平面与多层。适合“原理与模型边界”帮助链接。正文只作简短解释，不照抄厂商段落。
2. [SICK：Create 3D Point Clouds with a 2D LiDAR and an Encoder](https://sickag.github.io/sick_lidar_developer_guide/integration-notes/3d-with-2d-lidars/)：说明移动 2D、时间/姿态对应与坐标转换。适合三维形成补充阅读。
3. [Ouster：Coordinate System](https://docs.ouster.com/sensor-docs/firmware/coordinate-system)：真实光束角度、光学原点和坐标框架所需标定。页内强调使用课堂理想坐标约定，不能直接套到设备。
4. [Ouster：Motion Compensation](https://docs.ouster.com/sdk-docs/features/mapping/motion-compensation.html)：旋转扫描的一帧不是全场同一瞬间，运动可能造成点云畸变。作为扩展提示，不让入门学生承担实现要求。
5. [USGS：Lidar Base Specification Glossary](https://www.usgs.gov/ngp-standards-and-specifications/lidar-base-specification-glossary)：强度与分类是不同属性，强度还受入射角及设备设置等影响。适合颜色帮助。
6. [PCL：Using a matrix to transform a point cloud](https://pointclouds.org/documentation/tutorials/matrix_transform.html)：公共坐标系的旋转和平移。适合 A/B 叠加帮助。
7. [PCL：The PCD file format](https://pointclouds.org/documentation/tutorials/pcd_file_format.html)：XYZ/RGB 等字段、VIEWPOINT、ASCII / binary / binary_compressed 是不同存储类型。适合格式说明。

## 独立验收的关键问题

1. 光束末端、XYZ、点表、导出是否是同一个点？`r` 与 Euclidean norm、ToF 是否一致？
2. 隔着不透明挡板的点会不会被直接生成？无命中是否被当成范围端点？
3. 10° 与 1° 是否真正重算角度？点半径、旋转相机、切色是否改变点数量？
4. 单线是否只有指定截面，多线是否按真实仰角发射，而非对平面点竖直复制？
5. A/B 叠加是否用明确位姿转换；同一墙面能否相符？是否保留来源和未知？
6. 截面两端点及单位是否复核；任意两点是否被错误解释成净宽？
7. 导入单位 mm/cm/m、负坐标、大坐标、缺失颜色、ASCII PLY 属性乱序/PCD 附加字段是否正确？不支持的格式是否明确拒绝？
8. 桌面和 390 px 手机是否可看清点云、点选、控制与反馈，重复切实验及保存是否保持证据？ reduced motion、无 WebGL 时是否仍有可用解释和数据工具？
