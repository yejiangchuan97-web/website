# 任务5-2 · 钢筋绑扎工坊 · Anatomy Hero

[打开教学页面](index.html) · [深色页面](dark.html) · [返回总目录](../README.md)

教学主线：**对准交点，保持就位，完成绑扎，再复核结果。** 用操作任务导入，学生直接移动工具、绑扎、检查和处理疑点；页面没有选择题或答题评分。

本版参考“室内喷涂工坊”的空间和材质语言，重建为可旋转、缩放的真实三维绑扎工位。机械臂与工具头包含134个实体零部件，肩、肘、腕联动，工具保持垂直；钢筋为银灰金属，外壳为暖白，橙色和青绿色仅用于局部机构与状态。模型用同一归一化动作驱动绑丝、送丝轮、卷盘和扭结部件，暂停与拖动进度时保持一致。

## 三个入口

### 01 上岗挑战

第一段在钢筋作业台上完成四点绑扎。点选交点或点按钢筋区域移动枪口，方向键微调，空格或按钮启动一次绑扎。拖动场景旋转视角，滚轮或双指缩放；全景、正面、俯视和枪头按钮提供固定观察位置。必须实际对准并稳定后才可启动；重复绑同一点不会增加完成数。目标是准确完成，不以抢时间代替质量。

第二段明确切换到**另一组交点样例**，工具归位停稳并完成模拟停机隔离后才能人工检查。点选交点近看，进行模拟轻拉，发现漏绑或明显松动后标记、补绑，再重新复核。补绑期间检查操作锁定；补绑后需重新模拟停机隔离，重新轻拉检查，不会自动记为已复核。四点全部检查完才结束任务。

### 02 看懂这一扣

只讲一个小点：送丝轮推动绑丝，导向槽引导其绕过交点；轮子转了，并不等于绑丝已经绕全。绑丝必须包住交叉的两根钢筋，成扣后仍需检查。

保留“定位—夹持（就位约束）—送丝—扭结—离开”五步动画，支持慢放、拖动和定格。这里的“夹持”表示工具就位约束，不宣称所有机型均使用同一种主动夹爪。镜头直接靠近同一台绑扎头，打开检修侧盖观察卷盘、送丝轮和导向槽；不另换一幅固定示意图，也不扩展为整机原理课。

### 03 卡丝怎么办

先播放供丝受阻情境；未完成成环时锁定后续扭结。依次保留异常点、模拟停机隔离、查看供丝路径。正常对照与异常回放使用同一个动作模型。回到起点或重播时清除本次模拟处置状态，避免“已隔离”与工具仍运动同时出现。

## 资料依据与范围

- 课程依据：[原文对应任务](https://my.feishu.cn/wiki/UtqMwe7yti9zuJkBlLrcywi7nJe#doxcnpjZeYmLuiyF0C8Y56Qjw9d)，本地快照为[来源11](../来源/11_5.主体结构施工协同.txt)。
- 操作参考：[MAX RB441T / RB611T 官方说明书](https://www.maxusacorp.com/wp-content/uploads/TWINTIER-Manual-RB441T-RB611T.pdf)。英文部分 PDF 第16页说明中心对准及一次扳机动作；第17页要求垂直就位、绑扎自动停止前不移动；第19页列出松扣的不同可能原因。异常处理要求关闭主开关、锁止扳机、拆下电池，不能把暂停视为可清障。
- 机构参考：[MAX RB441T 官方产品介绍](https://www.maxusacorp.com/rebar_tying_tools/products/rb441t/)，用于区分送丝、回拉与折弯。这是具体机型资料，不作为所有机器人绑扎头的统一结构，也不是设备选购建议。

游戏容差、动作时长、送丝百分比和复核反馈均为教学设定，不对应真实设备的毫米精度、拉力、额定速度或验收阈值。卡丝停在归一化周期 0.51（送丝进度55%）只是可复现的演示事件。模拟轻拉只说明样例的预设状态，不能替代现场检查。具体机型的切断、回抽、收紧、扭结、折弯次序以手册为准。

页面不连接真实控制器，不发送上机程序。实际清障、补绑和复核须遵守设备规程、能源隔离要求和现场质量要求。

## 实现与验证

- `src/hero/concept.json`：Hero概念、分组零部件计划、证据与范围。
- `src/hero/page.html`、`style.css`：工坊布局、统一字体、移动端和明暗主题。
- `src/hero/model.mjs`：绑扎、隔离、检查、标记、补绑规则及归一化动作。
- `src/hero/scene.js`：Three.js实体机构、逆运动学、材质、灯光、接触示意、射线选点和镜头。
- `src/hero/app.js`：同一模型驱动的交互、播放和显示；实际工具姿态决定能否开始。
- `src/build.mjs` → `src/hero/build.mjs`：生成可直接双击打开、无网络依赖的 `index.html`、`dark.html`，内联仓库本地 Three.js 与许可证。
- 原 `src/geometry.mjs`、`figure-cache.json` 保留为无WebGL时的静态机构参考。旧版SVG应用源码和旧QA脚本不再是当前页面入口。

构建与检查（在仓库根目录运行）：

```text
node scripts/build.mjs 5-2
node --test 任务5-2_钢筋绑扎机器人操作与人工复核/qa/hero-model.test.mjs
node 任务5-2_钢筋绑扎机器人操作与人工复核/qa/hero-verify.mjs
node 任务5-2_钢筋绑扎机器人操作与人工复核/qa/hero-regression.mjs
node 任务5-2_钢筋绑扎机器人操作与人工复核/qa/hero-scene.mjs
```

此Hero采用与参考教程一致的Three.js透视渲染，真实深度缓冲决定遮挡；不是Anatomy SVG逐面排序器。单独检查关节连接、目标可达性、实际姿态门控、绑丝与钢筋的几何关系、相机视角及完整交互，不把旧静态SVG审计结果套用到三维工位。`--audit`参数会说明当前验证入口；它本身不宣称执行或通过原生SVG几何审计。

桌面采用主作业区与操作面板，支持全屏；手机自然纵向滚动，任务提示默认折叠，保留完整机械臂画面。减少动态效果时，游戏只在用户操作后显示结果；动作观察改为逐步推进。作业台或操作区可见时才运行动画，切至后台暂停且不补算时间。无WebGL时明确显示静态参考并禁用模拟操作。
